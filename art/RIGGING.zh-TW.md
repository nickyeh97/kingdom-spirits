## 1. 名詞

| 名詞 | 意思 | 在小獅身上 |
| --- | --- | --- |
| 骨架（Armature） | 一組骨頭，網格跟著骨頭動 | 物件 `Rig` |
| 骨頭（Bone） | 有頭（head）、尾（tail）的一段；旋轉時繞著「頭」轉 | `hips`、`head`、`thigh.L`… |
| 父子關係 | 子骨跟著父骨動（轉肩膀，整隻手跟著轉） | `root → hips → spine → neck → head` |
| 權重（Weights） | 每個頂點「跟哪幾根骨頭走、各佔多少」 | 頂點群組（Vertex Groups），名稱＝骨頭名 |
| 變形骨／控制骨 | 變形骨會帶動網格；控制骨只用來「操作」別的骨頭 | `foot_ik.L` 是控制骨，不帶網格 |
| FK（正向） | 從上往下一節一節轉（轉大腿→轉小腿） | 尾巴、頭、耳朵 |
| IK（反向） | 指定「腳掌要在哪」，電腦自動算出大腿、小腿要怎麼彎 | 四隻腳 |
| 約束（Constraint） | 骨頭的自動規則 | 小腿的 IK、腳掌的 Copy Rotation |
| Pose Mode | 擺姿勢、打關鍵影格的模式（R10：動作一律在這裡做） | 選 `Rig` → Ctrl+Tab |
| 關鍵影格（Keyframe） | 某一格的姿勢；中間的格子電腦自動補 | `I` 鍵插入 |
| Action | 一段動作（一組關鍵影格） | `Idle`、`Happy` |

## 2. 骨架長什麼樣（四足，小羊與小獅共用名稱）

```
root（地面，整隻移動／跳）
├─ hips（骨盆）
│  ├─ spine（背）
│  │  ├─ neck → head（頭）→ ear.L / ear.R、eye.L / eye.R（張眼）、lid.L / lid.R（閉眼）、mouth（嘴）
│  │  └─ upper_arm.L → forearm.L → paw.L（前腳；R 同）
│  ├─ thigh.L → shin.L → foot.L（後腳；R 同）
│  └─ tail.1 → tail.2 → tail.3
├─ hand_ik.L / hand_ik.R / foot_ik.L / foot_ik.R（IK 控制骨，不帶網格）
toy（玩具球，獨立的骨頭：不掛 root，小獅跳起來時球留在地上）
```

- **名稱共用**：所有四足模型的骨頭名稱一樣，Unity 才能共用同一組動作；但每個模型的骨頭位置與長度不同
  （寫在 `rig_quadruped.py` 的 `JOINTS`）。所以動作**只用旋轉**（加上 root／hips／IK 控制骨的移動），不改骨頭長度。
- **左右用 `.L`／`.R` 結尾**：Blender 認得這個規則，可以用「鏡像貼上姿勢」（Pose → Paste Pose Flipped）。
- **關節的「微彎」很重要**：前腳的肘往後、後腳的膝往前各彎一點點（看 `JOINTS` 的 `front`、`hind` 第二個點）。
  IK 會沿著這個方向繼續彎；如果放成完全直的，IK 不知道該往哪邊彎，可能反折。

## 3. IK 怎麼設（每隻腳三件事）

1. **小腿骨加 IK 約束**：目標＝那隻腳的控制骨，`Chain Length = 2`（往上管兩節：小腿＋大腿）。
2. **只准像真關節那樣彎**：大腿、小腿都鎖住 IK 的 Y、Z 軸（不能往旁邊扭），X 軸限制在 ±60°。
3. **腳掌跟控制骨同方向**：腳掌骨加 Copy Rotation（目標＝控制骨）→ 身體蹲下時腳掌還是平貼地面。
   ⚠️ 控制骨的方向**一定要跟腳掌骨一樣**；第一次試做時控制骨朝後、腳掌朝前，結果還沒動，四個腳掌就整個翻過去
   （`verify_rig.py` 的「休息姿勢網格不變形」就是為了抓這種錯）。

控制骨掛在 `root` 底下：跳的時候移動 `root`，四隻腳跟著一起離地；只蹲不跳的時候移動 `hips`，腳掌留在原地、膝蓋自己彎。

## 4. 權重怎麼算

Blender 的「自動權重」（Ctrl+P → With Automatic Weights）遇到很多零件疊在一起的 Q 版網格常常失敗，所以腳本自己算：

1. **頭的範圍**（含鬃毛、眼睛）整塊跟 `head`；耳朵附近跟 `ear.L/R`。邊緣 20% 平滑過渡到脖子。
2. **其他頂點**：找最近的兩根骨頭，越近佔越多（距離的 −4 次方），關節處自然平滑。
3. **小零件整塊同一組權重**：眼睛、鼻子、肉球這種小塊（< 250 個頂點）取平均 → 動的時候不會被扭變形。

想手動修：選 `Lion_Baby` → Weight Paint 模式，左邊選頂點群組（骨頭名），紅＝1、藍＝0。

## 5. 動作怎麼做

`rig_quadruped.py` 的第 5 段。每個動作：

```python
act = action("Idle", 60)                  # 新的 Action，0～60 格（30 fps＝2 秒）
key(15, hips={"loc": (0, 0, -0.012)},     # 第 15 格：骨盆往下 1.2 公分（吸氣）
        head={"rot": (0, 0, 5)})          #           頭歪 5 度
smooth(act, cyclic=True)                   # 曲線平滑；循環動作頭尾接起來
```

- 旋轉是「骨頭自己的座標」：**X＝前後彎（點頭）、Z＝左右擺**；Y 是沿著骨頭扭轉，盡量不用（容易看起來怪）。
- **活潑 vs 溫和**（組長裁決）：`style: "lively"`（小獅）幅度 1.0；溫和（小羊、鴿子）乘 0.55，節奏也會放慢。
- **預備動作**讓動作有生命：跳之前先蹲（Happy 第 6 格），落地再蹲一下緩衝（第 20 格）。
- **循環動作頭尾要一樣**（Idle 第 0 格＝第 60 格），不然 Unity 循環播放時會跳一下。

在 Blender 裡手動做一個動作：

1. 選 `Rig` → Pose Mode；下方 Timeline 或 Dope Sheet → Action Editor，按「New」建一個 Action 並命名。
2. 到第 0 格，選要動的骨頭（大多是 `hips`、`root`、控制骨、頭、尾巴），`I` → Location／Rotation 插關鍵影格。
3. 換到別的格子，`G`（移動）、`R`（旋轉）擺姿勢，再 `I`。腳：移動控制骨 `foot_ik.*`，不要直接轉大腿小腿。
4. 空白鍵播放檢查；Action 旁邊的盾牌圖示（Fake User）要打開，不然沒用到的 Action 存檔時會被丟掉。

### 5b. 六個動作（小獅幼體）

| 動作 | 長度 | 重點 |
| --- | --- | --- |
| Idle 待機 | 2 秒循環 | 呼吸、頭輕晃、尾巴擺、耳朵偶爾動 |
| Happy 開心 | 1 秒 | 蹲 → 跳（root 往上，腳跟著離地）→ 空中縮腳 → 落地緩衝 |
| Wave 揮手 | 1.5 秒 | 重心往後、右前腳抬到胸口、肉球朝前左右揮兩下 |
| Eat 吃果子 | 1.5 秒 | 低頭、`mouth` 骨上下放大＝張嘴咬兩下 |
| Sleep 睡覺 | 4 秒循環 | 趴下（hips 往下 12 公分，IK 把腳收起來）、前腳往前伸、尾巴捲、閉眼、慢呼吸 |
| Play 玩球 | 2 秒 | 球出現 → 前低後高 → 右前腳撥球、球滾 30 公分 → 小跳追過去 → 球收起來 |

### 5c. 「藏起來的零件」：閉眼與玩具球

骨架只能「移動、旋轉、縮放」，不能讓東西出現或消失。所以：

- 閉眼弧線、玩具球都**併進身體網格**（同一個材質），各自掛一根骨頭（`lid.L/R`、`toy`）。
- 平常把它們**縮成原本的 1%**（藏在眼睛裡、地上）；動作需要時把骨頭**放大 100 倍**＝原尺寸。
- 睡覺時反過來把張開的眼睛（`eye.L/R`）縮成 1%，露出閉眼弧線。
- 球的出現／消失用「常數插值」（瞬間切換），不會慢慢長大。

### 5d. 試做時踩到的坑（都已修正，檢查也補上了）

1. **控制骨方向**：IK 控制骨跟腳掌方向不同 → 腳掌複製旋轉後整個翻過去（「休息姿勢不變形」檢查會抓）。
2. **骨頭座標 vs 世界座標**：腳的控制骨是斜放的，它自己的「上」不是世界的上；用骨頭座標抬腳，
   腳掌反而往地下鑽、往前滑 3 公分。→ 控制骨一律用 `wloc`（世界座標的位移），腳本自動換算。
3. **離地與落地要直上直下**：一邊抬一邊往前，腳掌還沒離地就在滑（滑步檢查會抓）→ 先抬、再往前、在空中收回、再垂直放下。
4. **每個動作都要記錄所有骨頭**：「玩球」沒有記眼睛，結果沿用了「睡覺」的閉眼 →
   `rest_all()` 在第 0 格把每根骨頭都記一次休息姿勢；Unity 切換動作時也不會殘留上一個動作的姿勢。
5. **球不能掛在 root 底下**：root 是「跳」用的骨頭，掛在它底下的球會跟著飛起來。

6. **專用骨不能參加自動權重**（組長發現：吃果子時從側面看，鼻子被拉長）：鼻子離 `mouth` 骨很近，
   被「最近兩根骨頭」的規則分到一半權重，張嘴時就跟著被拉長。→ 眼睛、閉眼、嘴、玩具這些「專用骨」
   不參加距離權重、只帶指定的零件；頭的範圍往前延伸蓋住整個口鼻。`verify_rig.py` 加了一項檢查會抓這種「漏權重」。

### 5e. 同一支腳本做三個形態（成體、小領袖）

- `JOINTS` 每個模型一筆：關節位置是**量網格**來的（腿柱的 x、y，背和肚子的高度、嘴的位置），臉沿用幼體 ×1.1。
- **體型倍率 `k`**：同一個動作在成體身上移動距離要放大（肩高 0.56 ÷ 幼體 0.34 ≈ 1.6），否則成體的跳、揮手、趴下會變得很小。
- **鬃毛、皇冠跟頭走**：鬃毛垂到胸口，逐點判斷會被撕成兩半；改成「整塊零件的中心在頭範圍裡，整塊跟頭」。
  項鍊中心在頭範圍外，所以留在胸口。耳朵也是整塊中心在頭裡，所以耳朵的規則要排在後面（不然會被改回頭骨）。
- **三角形預算**：成體、小領袖本來就接近 8000，加了閉眼與球之後超過 → 這些小零件改用低面數（球 10×5、細線方形截面）。

### 5f. 小羊（溫和、沒有尾巴、羊毛一整塊）與「腳掌跟腿分開」的修正

- **腳掌跟腿分開**（組長發現，成體與小領袖）：「小零件整塊硬的」規則原本用「頂點數 < 250」判斷，
  整條腿頂點也少，被當成一塊硬的、不會在膝蓋彎，腳掌卻跟著 IK 走 → 分開。改成「實際尺寸 < 8 公分」才算小零件。
- **溫和**：`style: "gentle"` → 幅度 × 0.55、影格數 × 1.3（慢一點）。
- **沒有尾巴**：`tail: None` → 不放尾巴骨；動作裡寫到尾巴的地方自動略過（`key()` 遇到沒有的骨頭就跳過）。
- **耳朵改成「整塊零件」判斷**：小羊的耳朵水平插在毛帽的捲毛裡，用「耳朵周圍的球」會把旁邊的羊毛一起抓走；
  改成「中心在耳朵附近的整塊零件」才跟耳朵骨。小獅也一起改用這個規則。
- **羊角**：在頭的範圍外面，用 `head_parts`（羊角螺旋的中心）指定整塊跟頭。
- **三角形預算**：小羊成體、小領袖加了閉眼與球之後超過 8000 → 把最大的一塊（羊毛）**分離出來**減面約 3%、再併回去。
  試過「整個物件加 Decimate＋頂點群組限制」：群組外的小零件也被減掉，玩具球縮成一個點。

### 5g. 鴿子（鳥骨架，同一支腳本的 bird 分支）

- `JOINTS` 裡 `"kind": "bird"`：沒有前腳、沒有耳朵；兩隻腳用 IK（跟四足一樣）；多了**翅膀**（`wing` 肩→中間、`wingtip` 中間→翅尖）與一根**尾羽骨**（`tail.1`，整把扇子一起動）。
- **翅膀與尾羽是一片片零件**：用 `wing_box`、`tail_box` 指定範圍，中心落在範圍裡的整塊零件 100% 跟翅膀／尾羽骨，
  而且這些骨頭不參加距離權重 → 拍翅膀時不會扯到身體側面。
- 動作是同一組，但鳥的版本：
  - 開心：跳起來時張開翅膀；揮手：右翅膀張開往上、翅尖左右揮；玩球：沒有前腳，改成低頭用嘴啄球。
  - `wings(spread, lift, tip, only)` 幫忙算左右對稱的翅膀角度。
- 檢查：翅膀張開時外框本來就會變大，所以「網格大小 ±25%」只量身體（不算翅膀、尾羽）；翅膀的轉角上限放寬到 70°。

## 6. 怎麼檢查「沒有異常扭曲」（`verify_rig.py`）

| 檢查 | 為什麼 |
| --- | --- |
| 休息姿勢網格不變形（< 2 mm） | 約束或權重設錯時，還沒動就先變形 |
| 腳掌貼地時不滑步（< 1 cm） | 站著、蹲著的時候腳掌應該釘在地上 |
| 肘、膝不反折 | 關節只能往原本微彎的方向彎 |
| 骨頭轉角 < 45° | 太大的轉角在 Q 版身上會扭成奇怪的形狀 |
| 網格大小變化 < ±25% | 權重錯時網格會被拉長或壓扁 |
| 循環動作頭尾一致 | Unity 循環播放不跳格 |

這些檢查都有「故意弄壞」驗證過會抓到錯（工作日誌 `docs/art-worklog/2026-10-29_005`）。檢查過了還是要看算圖或在 Blender 播放，數字不等於好看。

## 7. 匯出到 Unity

- FBX 匯出時：只匯出變形骨（`Only Deform Bones`），控制骨與 IK 的效果「烘」進每一格；每個 Action 變成一段動畫（take）。
- Unity 端：`Assets/Editor/BeastModelImporter.cs` 把靈獸模型設成 **Legacy 動畫**；`BeastView` 用名稱播放
  （待機循環、點一下播 Happy 再回到待機）。動作名稱在 Unity 裡叫「Rig|Idle」，程式比對「|」後面的名字。
- 沒有骨架的模型照舊用程式動作（整隻跳、轉圈）。
