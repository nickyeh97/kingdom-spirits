## 0. 一句話定義

**每個孩子有一隻自己的靈獸，隨著孩子的服事一起長大。**
靈獸不是獎品，是孩子服事之路的「見證者與夥伴」；它記錄孩子自己的成長軌跡，不跟任何人比。

## 1. 目標與非目標

### 1.1 目標（依序）

1. **強化內在動機**：讓孩子甘心樂意地服事，並在服事中享受聖靈的果子；靈獸與鼓勵話語是「陪伴與見證」，不是「交換條件」。
2. **取代紙本服事經歷卡的電子呈現**：家長看到紙本卡有老師簽名後，主動為孩子登錄一次服事；系統以「服事項目等級」與「靈獸進化」呈現。
3. **服事平台的異象檢核**：自我形象（靈獸從第一天就在，不是服事之後才給）、品格塑造（鼓勵話語以經文與聖靈果子為底）、活出計畫（服事累積看得見）。

### 1.2 非目標（明確不做）

- 不做任何孩子之間的比較、排行、展示牆、分享他人靈獸（紅燈 #1）。
- 不做留存機制：沒有每日登入、連續簽到、饑餓/衰弱/忽略懲罰、倒數計時、推播提醒（紅燈 #2）。
- 不做隨機獎勵、轉蛋、抽卡、內購、廣告（紅燈 #3、#4）。
- 不以停留時間為成功指標（紅燈 #5）；一次開啟 3–5 分鐘看完就關掉，是**正確**的使用方式。
- 不蒐集平台以外的任何兒童資料（紅燈 #6）；遊戲不做聊天、不做任何跨帳號的社交功能。
- 不做「戰鬥、捕捉、餵養、繁殖」等幻獸類遊戲的核心玩法——只借鏡其**美術風格**（見 §7）。

### 1.3 成功怎麼看（可驗證的成功準則）

| 準則 | 驗證方式 |
| --- | --- |
| 家長能在 1 分鐘內完成「登錄一次服事 → 看到靈獸變化」 | 測試帳號實際操作計時 |
| 孩子在沒有服事的期間開啟遊戲，看到的靈獸**與上次一模一樣、狀態完好** | 不存在任何衰退邏輯（單元測試＋人工檢核） |
| 遊戲畫面上找不到任何其他孩子的資料 | RLS 只回自己孩子；UI 沒有任何列表他人的入口 |
| 手機瀏覽器（iOS Safari / Android Chrome）首次載入 ≤ 10 秒（4G） | Web 建置壓縮後 ≤ 15 MB；實機量測 |
| 守則檢查清單（DESIGN_PRINCIPLES §4）七項全部打勾 | 每個 Sprint 結案時重過一次 |

## 2. 使用者與情境

- **孩子（主要體驗者）**：兒童班，約 6–12 歲；看得懂注音或簡單國字；用家長的手機操作。
- **家長（操作者、守門人）**：登入牧區平台後，從「服事卡」頁點連結進入遊戲；負責登錄服事次數、設定鼓勵話語。
- **同工／老師（間接）**：在紙本卡簽名（現況流程不變）；該班老師可在平台端唯讀檢視孩子的服事卡（關懷、與紙本核對）。
- **目前只開放兒童班**：幼幼班不納入（無服事項目，2026-09-17 裁決）；**幼童班暫不開放**（2026-10-03 裁決，與平台兒童服事目前只適用兒童班一致）。平台端只對兒童班的孩子顯示入口。

**典型情境**：聚會後回家，孩子拿出老師簽過名的紙本卡。家長打開平台 → 服事卡頁 → 「去看靈獸 ▶」→ 家長在遊戲裡按「＋1 服事」選擇項目 → 孩子挑一顆「這次嘗到的果子」→ 靈獸慶祝（若跨過門檻就進化）→ 出現家長預先寫好的鼓勵話。整段 1–3 分鐘。

## 3. 核心迴圈與數值

### 3.1 核心迴圈

```
真實服事（教會現場，老師簽名紙本卡）
   → 家長在遊戲登錄一次服事（項目；紀錄時間＝按下儲存的時刻；可選：孩子挑一顆聖靈果子）
   → 該項目等級 +1；總次數 +1
   → 靈獸慶祝；跨門檻則進化到下一階段
   → 顯示家長的鼓勵話（或天父的話）
   → 關掉遊戲，回到生活（沒有下一個任務、沒有倒數）
```

### 3.2 服事項目與等級

服事項目**直接沿用平台的字典** `child_service_items`（目前固定六項：收奉獻、敬拜-司琴、敬拜-小樂器、敬拜-Vocal、領讀天使-宣言/讀經/禱告、環境稽核）。遊戲不自建項目清單，字典改動由平台同工維護。

- **項目等級 = 該項目累計次數 + 1**（`level = count + 1`；組長裁決 2026-09-17）：尚未服事過的項目是**一等**（預設），第一次服事就升到**二等**，之後每服事一次升一等。
- 尚未服事過的項目以「等你來探索」呈現（一扇還沒打開的門，柔和、不灰掉、不打叉），並附一句邀請語；**不出現「缺少」「尚未完成」等字眼**。

### 3.3 靈獸成長階段

靈獸階段由**所有項目的總次數**決定，門檻為設定值（放在 `Assets/Config/GrowthConfig.asset`，非寫死）：

| 階段 | 名稱 | 總次數門檻（預設） | 外觀重點 |
| --- | --- | --- | --- |
| 1 | 初生 | 0 | 幼體：頭身比 1:1、圓潤、大眼 |
| 2 | 成長 | 4 | 少年體：體型放大、四肢/翅膀展開、多一個花紋 |
| 3 | 茁壯 | 12 | 成體：完整輪廓、有標誌性特徵（鬃毛/尾羽/角） |
| 4 | 小領袖 | 24 | 成體＋光暈與披風/冠冕類配件，站姿更穩 |

設計理由：教會每週聚會一次，一位孩子大約每月服事 1–3 次，一年約 10–30 次；門檻 4 / 12 / 24 對應「約一個季度 / 半年 / 一年多」看到一次進化，讓成長有節奏感又不會太久沒變化。**永遠不會退階**。

**不顯示「距下一階段」的進度條或「還差 N 次」**（組長裁決）：孩子看到的是現在的靈獸與服事卡，進化是驚喜，不是倒數。

**第一天就有靈獸**：孩子第一次進入遊戲就選一隻靈獸（初生階段，完整可愛），不是「先服事才有」。這是異象第一點「自我形象：確信天父孩子的身分」的直接落實——身分是白白得的，服事是回應。

### 3.4 靈獸變體與顏色

- **變體（species）**：首發 3 種、擴充到 6 種，全部取材自聖經中的動物，每種附一句錨定經文（同時是鼓勵話語的來源）：

| # | 顯示名稱（英文） | 原型 | 程式 id | 經文錨點 | 首發 |
| --- | --- | --- | --- | --- | --- |
| 1 | **Lamb** | 小羊 | `lamb` | 詩篇 23:1、約翰福音 10:14 | ✅ |
| 2 | **Dove** | 鴿子 | `dove` | 馬太福音 3:16 | ✅ |
| 3 | **Lion** | 小獅 | `lion` | 啟示錄 5:5 | ✅ |
| 4 | **Deer** | 小鹿 | `deer` | 詩篇 42:1 | 擴充 |
| 5 | **Eagle** | 雛鷹 | `eagle` | 以賽亞書 40:31 | 擴充 |
| 6 | **Fish** | 小魚 | `fish` | 馬太福音 4:19 | 擴充 |

- **靈獸名稱一律以英文顯示**（組長裁決 2026-09-30）：挑選畫面（S1、S4）與主畫面的靈獸名都用上表的英文名稱；中文原型只出現在文件與同工端。命名功能上線（Phase 2）前，主畫面的靈獸名＝英文變體名。

- **變體可以隨時更換**，成長進度屬於孩子而不屬於某一隻靈獸：換變體不重來、階段照舊。
- **顏色**：8 組預設配色（主色＋副色＋點綴色），孩子點選即套用；**不開放自由調色**（維持美術一致、避免出現不合適的配色、實作簡單）。技術上以「頂點色配色遮罩 + 材質參數」達成一組網格多種配色（§7.2；著色器 `SpiritBeast/PaletteMask`）。

### 3.5 鼓勵話語系統

三種來源、統一一個顯示位置（靈獸旁的對話框），每次最多一句：

| 來源 | 內容 | 何時出現 |
| --- | --- | --- |
| **家長的話** | 家長在平台預先寫的 1–5 句（每句 ≤ 40 字） | 開啟遊戲時隨機一句；登錄服事後必出一句 |
| **天父的話** | 內建經文池（腓立比書 4:8 審稿、非比較性），含變體錨定經文與聖靈果子九項 | 家長沒寫時的預設；進化時 |
| **邀請** | 針對「等你來探索」的項目，一句柔和的邀請（例：「下次想試試看『領讀天使』嗎？」） | 只在登錄服事的慶祝之後、最多一句；**開啟遊戲時不出現**（避免每次開啟都被提醒「還有沒做的」） |

**聖靈果子反思**（登錄服事流程中、可跳過）：問孩子「這次服事，你嘗到哪一顆果子？」，九顆果子圖示點一下即可（仁愛、喜樂、和平、忍耐、恩慈、良善、信實、溫柔、節制）。所選果子存在該筆紀錄上，家長在平台的服事卡歷史看得到（例：`2026/09/12 收奉獻 · 喜樂`）。這是給孩子自己回味的，不計分、不統計、不排名。

**文案守則**（腓 4:8 ＋ 紅燈 #7）：
- 只肯定「孩子本身」與「行動本身」，不出現任何與他人比較的字（不用「比別人」「最棒的一個」「第一名」）。
- 不用罪惡感（不用「好久沒來了」「靈獸想你了」）。
- 內建經文池初稿見附錄 A。

### 3.6 內在動機的設計依據（簡述）

以自我決定理論（自主、勝任、連結）作為檢核：
- **自主**：孩子自己選靈獸、選顏色、選果子；遊戲沒有指派任務、沒有「必須做的事」。
- **勝任**：每個階段的靈獸都是「完整、好看」的，一等不是「弱」，是「開始」；成長看得見但不催促。
- **連結**：家長的話、天父的話，讓服事連回關係——對家人、對神——而不是連回分數。

## 4. 畫面與流程（MVP）

所有畫面**直式、單手可操作、按鈕 ≥ 44pt**；文字用 Noto Sans TC 子集（§8.4）。

| # | 畫面 | 內容 | 互動 |
| --- | --- | --- | --- |
| S0 | 入口/載入 | 讀取網址片段內的授權（§6.2）、拉資料；失敗顯示「請從平台重新開啟」 | 無 |
| S1 | 第一次相遇（僅無靈獸資料時） | 「天父為你預備了一位夥伴」→ 三隻初生靈獸並排（名稱以英文顯示：Lamb／Dove／Lion）→ 點選 → 選配色 → 完成 | 點選、確認 |
| S2 | 靈獸之家（主畫面） | 靈獸待機動畫；上方：靈獸名（英文變體名，如 Lamb）＋階段名；下方三顆鈕：服事卡、換裝扮、＋1 服事 | 點靈獸→小反應動畫（跳一下/眨眼）；沒有其他玩法 |
| S3 | 服事卡 | 六項服事：圖示＋等級；未探索者顯示「等你來探索」；下方近 10 筆紀錄（日期・項目・果子） | 唯讀 |
| S4 | 換裝扮 | 變體（3）＋配色（8）即時預覽 → 儲存 | 點選、儲存 |
| S5 | ＋1 服事（家長操作） | 步驟：①「我是家長，已看到老師簽名」勾選 → ②選項目（六格）→ ③選果子（可跳過）→ ④確認 → 儲存（紀錄時間＝按下儲存的時刻） | 全部點選，**沒有文字輸入** |
| S6 | 慶祝 | 升等：靈獸開心動畫＋粒子；進化：3 秒進化過場（光→新形態）＋階段名；之後顯示一句鼓勵、可選一句邀請 | 點一下結束 |

**不做的畫面**：設定、通知、成就牆、排行、好友、分享。

> 家長勾選「我是家長」只是 UX 守門（避免孩子自己按），**不是安全邊界**；真正的邊界是 RLS（只有綁定家長的帳號能寫入）。

## 5. 與牧區平台的分工

原則：**文字輸入在平台、觸控互動在遊戲**。Unity Web 在手機瀏覽器的中文輸入法體驗很差，因此凡需要打字的都留在平台（Vue）。

| 功能 | 平台（Vue＋Supabase） | 遊戲（Unity Web） |
| --- | --- | --- |
| 登入、選孩子、進入遊戲連結 | ✅ 服事卡頁（家長端） | — |
| 鼓勵話語編輯（1–5 句） | ✅ | 唯讀顯示 |
| 登錄一次服事（＋1） | 檢視歷史、**刪除誤登**（限本人登錄的） | ✅ 主要入口（S5） |
| 選變體、選配色 | — | ✅（S4） |
| 服事卡檢視 | ✅（表格：項目等級＋歷史，含果子） | ✅（S3） |
| 資料儲存 | ✅ Supabase（同一專案、同一 RLS） | 無後端、無本地存檔（僅快取「上次看到的總次數」以判斷是否播進化） |

平台端需新增（屬平台 repo 的工作，非本 repo）：
1. Migration：`service_card_entries`、`beast_profiles` 兩張表＋RLS（§6.1）。
2. 家長端「服事卡」頁：鼓勵話語編輯、歷史檢視/刪除、「去看靈獸 ▶」連結（帶授權片段，§6.2）。
3. `docs/HANDBOOK.md` 增加家長操作說明。

## 6. 資料契約與安全

### 6.1 資料表（放在平台的 Supabase，migration 於平台 repo）

```sql
-- 服事經歷卡：每登錄一次服事一筆（家長看到老師簽名後登錄）
create table service_card_entries (
  id uuid primary key default gen_random_uuid(),
  child_id uuid not null references children (id) on delete cascade,
  item text not null,                 -- 值同 child_service_items.name
  fruit text,                         -- 聖靈果子反思（九項之一，可空）
  recorded_by uuid not null default auth.uid() references profiles (id),
  created_at timestamptz not null default now() -- 紀錄時間＝家長按下儲存的時刻（§10 #4）
);
create index idx_service_card_child on service_card_entries (child_id);

-- 靈獸設定：每孩一筆
create table beast_profiles (
  child_id uuid primary key references children (id) on delete cascade,
  variant text not null,              -- lamb | dove | lion | deer | eagle | fish
  palette text not null default 'p1', -- p1..p8
  encouragements jsonb not null default '[]', -- 家長的話：string[]，≤5 句、每句 ≤40 字
  updated_by uuid not null default auth.uid() references profiles (id),
  updated_at timestamptz not null default now()
);
```

**RLS 意圖**（實作在平台 `rls.sql`）：

| 表 | select | insert | update | delete |
| --- | --- | --- | --- | --- |
| `service_card_entries` | 綁定家長、**該班老師（唯讀）**、admin | 綁定家長、admin | 不開放 | 綁定家長（限 `recorded_by = auth.uid()`）、admin |
| `beast_profiles` | 綁定家長、admin | 綁定家長 | 綁定家長 | 不開放 |

「綁定家長」＝ `family_links` 有 `(auth.uid(), child_id)`；「該班老師」＝ `teacher_class_assignments` 涵蓋該孩子的班別；沿用平台既有的 `is_admin()` 等函式。老師可讀（關懷、與紙本核對）但不可寫，登錄一律由家長（組長裁決 2026-09-17）。

派生值（等級、階段）**不存資料庫**，由遊戲與平台各自從 entries 計算；計算規則放在遊戲的純 C# 核心（§8.2）與平台的 `src/lib/` 各一份，並有相同的測試案例確保一致。

### 6.2 授權交接：平台 → 遊戲

- 平台開啟遊戲的連結格式：`https://<遊戲網址>/#at=<access_token>&child=<child_id>`
  - 使用 **URL 片段（`#`）**：片段不會送到伺服器、不進存取記錄；與 Supabase OAuth 回呼相同的做法。
  - **只傳 access token（預設 1 小時效期），不傳 refresh token**；過期就回平台重開，遊戲不做續期。
- 遊戲的 `index.html` 在 Unity 載入前讀取片段、存在記憶體、立刻 `history.replaceState` 清掉網址列，待 Unity 就緒後以 `SendMessage` 傳入。
- 遊戲直接呼叫 Supabase REST（PostgREST）：`Authorization: Bearer <at>` ＋ `apikey: <anon key>`；anon key 是公開值，安全邊界是 RLS。
- 遊戲對 `child` 參數不做信任：查不到資料（RLS 過濾）就顯示「無法讀取，請從平台重新開啟」。

### 6.3 個資最小化

遊戲從平台取得的資料**只有**：`children.name`（顯示用；若日後平台加「暱稱」欄位則優先用暱稱）、該孩子的 `service_card_entries`、`beast_profiles`、`child_service_items` 字典。**不取**生日、班別、家長資料、其他孩子。遊戲不寫任何分析/追蹤事件，不接第三方 SDK。

## 7. 美術方向（Art Bible 摘要）

### 7.1 風格參考與著作權界線

參考《幻獸帕魯（Palworld）》的**風格語彙**：圓潤低多邊形、頭身比大、飽和但柔和的配色、cel-shading（卡通著色）＋細描邊、簡潔材質、可愛表情。
**只借鏡風格，不得複製任何帕魯角色的造型、名稱、配色組合或標誌性特徵**（著作權）。所有靈獸為原創設計，以聖經動物為原型（§3.4）。

### 7.2 每隻靈獸的資產需求

| 資產 | 數量（首發 3 種） | 說明 |
| --- | --- | --- |
| 網格 | 每種 2 個（幼體、成體） | 階段 1–2 共用幼體網格、階段 3–4 共用成體網格；階段內差異用縮放、花紋遮罩、配件與光暈達成，把建模量減半 |
| 動畫 | 待機、開心（點擊反應/升等）、進化過場 | 共用人形/四足骨架各一套，動畫可跨變體重用 |
| 配件 | 階段 4 用：光暈＋一件披風/冠冕 | 通用件，全部變體共用 |
| 配色遮罩 | 每網格：**頂點色屬性 `Mask`**——A=1 時 RGB 三通道對應主/副/點綴色槽；A=0 時 RGB 即固定色（眼睛、鼻子、蹄等） | 一組網格 × 8 配色不用重出貼圖；不需展 UV、幾乎不增加下載量（2026-10-02 決定，取代原「配色遮罩貼圖」） |
| 花紋 | 隨成長加上：階段 2 起出現花紋（階段越高花紋越完整），以**花紋遮罩貼圖**（需展 UV，≤ 512²）＋材質的「階段」參數控制顯示 | 花紋要畫在零件中間，頂點色做不到，所以只有花紋用貼圖；因階段 2 共用幼體網格，**幼體網格也要展 UV** |
| 圖示 | 六項服事圖示、九顆果子圖示、八組配色色票 | 2D，扁平風 |

**產製途徑**（§10 #7 裁決）：**先試 AI 以文字 prompt 生成模型、在 Blender 整理**；成果不佳再改買素材包改造。操作步驟、工具比較與授權注意事項見 `docs/ART_PIPELINE.md`。無論哪條路，**最終資產必須是原創或授權合規**。

### 7.3 效能預算（手機 Web）

- 場景同時只有一隻靈獸：≤ 8k 三角形（成體）、貼圖 ≤ 1024²、單一材質。
- 粒子與後製只在慶祝 3 秒內出現；平時 30 fps 即可（Web 上不追 60）。
- Web 建置壓縮後 **≤ 15 MB**（含字型子集、3 變體 × 2 網格）。

## 8. 技術架構

### 8.1 選型（已決）

| 層 | 選型 | 說明 |
| --- | --- | --- |
| 引擎 | **Unity 6.3 LTS（6000.3.25f1）** | 建置目標 **Web**（Unity 6 起正式支援手機瀏覽器） |
| 渲染 | URP ＋ 簡易 toon 著色器（描邊＋色階） | 手機 Web 可負擔 |
| UI | UGUI ＋ TextMeshPro（Unity 6 併入 UGUI 套件） | 直式版面、單一 Canvas |
| 資料 | UnityWebRequest 直呼 Supabase REST；JSON 用 Newtonsoft（`com.unity.nuget.newtonsoft-json`） | 不引入 Supabase C# SDK（Web 相容性與體積） |
| 測試 | Unity Test Framework（EditMode 為主） | 純 C# 核心邏輯不依賴 UnityEngine，跑得快 |
| 命令列 | Unity CLI（`unity install`）安裝編輯器；Editor `-batchmode` 建置與跑測試（§8.5） | 建置與測試**不需要人手點編輯器** |
| 託管 | Vercel 或 Cloudflare Pages 靜態站（免費額度） | 需設定 `.br`/`.gz` 的 `Content-Encoding` 標頭 |
| CI | GitHub Actions（game-ci/unity-builder ＋ unity-test-runner） | PR 跑測試；main 建置 Web 並部署 |

**為什麼不直接在平台用 Vue/Three.js 做？** 那是更簡單的路（沒有第二個 repo、沒有授權交接、沒有 15 MB 下載）。組長已決定採 Unity 以取得 3D 角色與動畫的表現力；本文件把 Unity Web 在手機上的風險（載入時間、記憶體、中文輸入）列為硬性約束並逐一規避（§5、§7.3、§8.4）。**若 G0 驗證（§9）在實機載入超過 10 秒且無法壓下，回頭重議此決定。**

### 8.3 核心邏輯規則（Core，必有測試）

```
count(item)      = entries 中 item 相同的筆數
level(item)      = count(item) + 1                     // §3.2：預設一等，第一次服事二等
total            = entries 筆數
stage(total)     = thresholds 中 ≤ total 的最大索引 + 1 // thresholds 預設 [0, 4, 12, 24]
evolved(prev, now) = stage(now) > stage(prev)          // 用於判斷是否播進化過場
```

邊際測試至少涵蓋：0 筆、剛好門檻、門檻−1、超過最高門檻、未知 item（字典已停用的舊紀錄仍計數）、片段缺參數／多餘參數／token 含 URL 編碼字元。

### 8.4 中文字型

TextMeshPro 動態字型在 Web 上成本高；改為**靜態字型圖集**：以 Noto Sans TC 建立子集（介面文案 ＋ 經文池 ＋ 服事項目名稱 ＋ 常用 3000 字保險），建置前由腳本自動收集 `Assets/Config` 內所有字串產生字元清單。

### 8.5 命令列作業（開發者與 AI 協作者都走這條路）

```bash
# 建置 Web（於 CI 與本機皆相同）
Unity -batchmode -nographics -quit -projectPath . \
      -executeMethod SpiritBeast.Editor.Build.Web -logFile -

# 跑 EditMode 測試
Unity -batchmode -nographics -projectPath . \
      -runTests -testPlatform EditMode -testResults results.xml -logFile -
```

Unity 版本以 `ProjectSettings/ProjectVersion.txt` 為準；安裝、測試（含免授權的 `dotnet test Tools/CoreTests`）、建置與 CI Secrets 的完整步驟見 `docs/DEVELOPMENT.md`。
