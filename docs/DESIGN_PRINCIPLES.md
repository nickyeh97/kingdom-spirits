# 設計守則：合乎神的義

> 這是 TBOJ 計畫的**最高守則**。在任何教材、功能、設計被建立之前，都必須先通過本文件的檢核。
> 若有任何設計與本守則衝突，**立即停下、提出討論**，不得便宜行事。

> 「這樣，信心若沒有行為就是死的。」— 雅各書 2:17
> 「凡是真實的、可敬的、公義的、清潔的、可愛的、有美名的……這些事你們都要思念。」— 腓立比書 4:8

---

## 0. 為什麼需要這份守則

科技教育很容易在不知不覺中，用「成長指標」與「使用者黏著度」之名，餵養孩子的驕傲、嫉妒、貪婪與成癮。
本計畫的存在不是為了做出「最會留住孩子的 App」，而是為了**服事孩子、不操控孩子**。

因此，每一個設計決策都要先回答一個問題：

> **這個設計，是在「服事」這個孩子，還是在「利用」這個孩子？**

| 主題 | 經文 | 對應原則 |

## 2. 🔴 紅燈規則（禁止）

任何設計**不得**包含以下機制：

1. **比較式排行榜 / 公開排名** — 違反加 5:26、6:4。會餵養驕傲與嫉妒，牴觸「自我認同」的培養。
2. **成癮式留存機制** — 連續登入壓力、無限刷、用罪惡感逼迫回訪。違反林前 6:12。
3. **對弱勢或兒童投放廣告** — 違反雅各書服事困苦人的核心。
4. **將核心學習內容設付費牆，排除付不起的孩子** — 同上。
5. **以「停留時間 / 觀看時長」作為成功指標** — 真正的成功是學會與成長，不是黏著度。
6. **蒐集非必要的兒童個資、或將兒童資料用於商業用途** — 馬太福音 18:6。
7. **任何可能羞辱、標籤化、貶低孩子的設計**（公開失敗、公開落後）。

## 3. 🟢 綠燈規則（鼓勵，並可引經據典）

1. **自己跟自己比的成長軌跡** 取代與他人比較 — 加拉太書 6:4。
2. **兒童保護是系統第一優先**，安全永遠高於成長與營收 — 馬太福音 18:6。
3. **內容以腓立比書 4:8 為審稿標準**：真實、可敬、公義、清潔、可愛。
4. **弱勢與偏鄉優先**，最需要的人最先得到 — 馬太福音 25:40。
5. **降低門檻、不攔阻**：免費、易取得、低頻寬可用 — 馬可福音 10:14。
6. **賦能教師、建立傳承鏈**，而非只服務終端使用者 — 提摩太後書 2:2。
7. **培養同理心與自我認同**作為明確的教育目標，與學科並重。

## 4. 設計檢查清單（每個新教材 / 功能上線前必過）

- [ ] 這個設計服事孩子，而不是利用孩子？（林前 6:12）
- [ ] 沒有比較、排名、或任何會羞辱孩子的機制？（加 6:4）
- [ ] 內容通過腓立比書 4:8 的審稿（真實、可敬、公義、清潔、可愛）？
- [ ] 最弱勢的孩子也用得到（免費、低門檻、低頻寬）？（太 25:40）
- [ ] 沒有蒐集非必要的兒童個資？兒童安全高於一切？（太 18:6）
- [ ] 有沒有培養同理心或自我認同的成分？
- [ ] 若有任何一項打勾不下去 → **停下，提出討論。**

---

## 5. 兒童保護憲章（Phase 5 的最高憲法）

> 「凡使這信我的一個小子跌倒的，倒不如把大磨石拴在這人的頸項上，沉在深海裡。」— 馬太福音 18:6

任何允許成人與兒童互動的功能（如智能導師、輔導員系統），都必須：

1. **AI 不得單獨面對孩子處理情感/諮商議題**，必須有真人輔導員在迴路中。
2. 任何回報兒童受傷害風險的機制，**安全永遠優先於隱私與營收**。
3. 系統預設「保護」，而非預設「開放」。
