# 3D 資產需求描述模板 — 繁體中文閱讀與填寫副本

模板版本：1.1。適用 skill：0.1.6。[英文正本](user-request.template_EN.md)為正式依據；本副本方便使用者閱讀、複製與填寫。

知道的先填，不確定就寫「請先建議」，不需要就寫「不需要」。不必懂完整技術名詞，先描述想得到的結果，我會協助轉成製作規格。範例只是選項，不會自動成為預設值。填完模板是提供需求，尚未表示同意其中未確定的建議。

先用下面的基本版；Rig 與進階規格有需要才補。參考資料請附檔案或連結；若資料夾有多個模型，請指出這次要做哪一個。未能讀取的資料，我必須明確說明。

## 缺少資訊與提問語言

即使使用者用自由文字描述、沒有填表，也要主動詢問基本模板中尚未提供且適用的項目。提問、解釋選項與需求總結，配合使用者正在使用的語言或明確指定的語言；技術通道名稱可保留英文。儲存的 skill、brief 與 worklog 仍以英文為正本。沿用已提供或已確認的答案；空白代表缺少資訊，不代表「不需要」或允許自行猜測。使用者不知道時，提出具體選項與取捨，把建議納入確認摘要；明確授權判斷可以結案，沉默不可以。相關缺項分組詢問，保留未答項目，等待時可繼續分析參考。先確認 Rig 是否不需要／保留／新增；不需要 Rig 時，其細節不適用。同樣，不交付渲染圖時，打光與圖片設定可記為不適用。不強迫填無關的進階欄位，也不重問已有答案的項目。

此外仍需知道模型名稱、工作／輸出資料夾、要保留的來源版本，以及相關 Blender／接收軟體版本；已有脈絡就沿用，缺少才問，不必在基本表格重複填寫。

## Rig 補充 — 描述行為，不只寫「加 Ctrl」

本專案使用 Armature 的 Pose Mode 骨架控制器。需要時，每個控制器各填一份；用自然語言說明也可以。

```text
All Ctrl 要帶動什麼；父子階層：
控制器名稱或用途：
必須跟著它一起移動的零件與細節：
使用者操作 → 物件反應（例如向上移動會帶動旋轉）：
位移、旋轉、縮放哪些可動／鎖定；局部或世界座標（若知道）：
行程、角度、螺距、方向、限制（或請先建議）：
初始狀態／過渡中／脫離後，分別可以做什麼：
如何還原、接回、關閉或反向操作：
關鍵影格、播放、循環與輸出需求：
線材或軟物件：彎曲、端點與是否允許伸長：
需要物理／碰撞模擬，還是只需動畫控制：
```

## 進階補充 — 有接收流程規定時再填

```text
單位／朝向軸／原點／命名／Collection 規則：
基礎與最終計算面數、LOD、輸出時是否三角化：
UV 像素密度、島間距、接縫、共用限制：
UDIM 格號、各格與通道解析度：
Normal 軸向慣例、貼圖位元深度、通道打包、色彩空間：
貼圖格式與物件類別／共用圖集資料夾要求：
輸出格式與版本、需要在哪個引擎／DCC 驗證：
Rig 輸出限制、骨骼命名與變形要求：
```

拓樸選「其他」時，先詢問具體表示方式、可編輯與輸出時的拓樸需求；若與現有三角形／四邊形慣例不同，納入本資產的完整摘要釐清，使用者明確要求優先。不直接禁止此選項，也不視為無限制允許 n-gon。

不要把酒瓶試作的數字當成通用預設：1,375 個四邊形、2K 圖集與螺紋行程都是該瓶子的規格。一套 UV 可以對應多張通道貼圖，也可以配合多個材質。面數與換算三角面數不同：1,000 個四邊形三角化後是 2,000 個三角形。烘焙能保留表面光影細節，不能代替輪廓、厚度與正確折射所需的幾何。

## 已有專案規範 — 不必每次重填

保留可編輯、有明確命名的零件、合規拓樸及每個網格都有可用 UV；開案時決定的風格模式（PBR 模式用四個實際 PBR 貼圖通道；NPR 模式用配色遮罩或調色盤加描邊）；目標引擎的匯出設定；由左到右整理材質節點，Texture Coordinate → Mapping 連到每張圖片；貼圖按物件類別或有說明的共用圖集分類；保留來源並另存版本；開啟物件／Collection 選取與視窗 overlays／Extras；按需求檢查模型、UV、材質、rig 並重開檔案；每次用英文 worklog 記錄需求、行為、驗證、取捨與回饋。新要求與既有規範有衝突時，我必須指出並釐清。這些規範不會代替本次資產的需求確認。

## 檢視成品後的回饋模板

```text
檢查的檔案／版本；哪個物件、材質或控制器：
已經滿意、請保留的部分：
目前的問題（可附圖片、影格或重現步驟）：
希望改成什麼樣子、如何判斷完成：
優先程度：必修／改善／有餘裕再做：
這次範圍：只記錄分析／先整理修正摘要給我確認／執行已確認的修正：
```

例如「材質很好」代表對指定版本該部分的肯定，不會被擴大解讀為其他拓樸、rig 或未來版本都通過。我會記錄回饋範圍，對實質變更的要求先總結確認。
