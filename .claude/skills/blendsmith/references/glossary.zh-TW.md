# blendsmith 術語表 — 繁體中文閱讀副本

版本：**2026.09.011-ks.1**。英文正本為 [glossary.md](glossary.md)；兩者需同版本同步更新。

這份術語表是給「正在學 3D 建模」的人看的。每個術語盡量回答四件事：

- **是什麼**：一句話說清楚。
- **為什麼重要**：不注意會出什麼問題。
- **小羊的例子**：我們在 `art/blender/` 做小羊時實際碰到的情況。
- **在 Blender 哪裡**：去哪裡找、怎麼操作。

括號內是英文原文，看英文文件或搜尋教學時用得到。規則編號（R01–R12）對應 [SKILL.zh-TW.md](../SKILL.zh-TW.md)。

## 1. 流程與文件

**參考（Reference）**
- 是什麼：建模依據的照片、圖稿、實物或規格。
- 為什麼重要：沒有參考，比例和細節只能靠猜；猜錯就要整個重做。R04 要求先分析參考，分清「看得到的事實」和「推測」。
- 小羊的例子：你給的真實綿羊照片，讓我們知道臉是一塊被毛包圍的白色區域、耳朵是從毛裡水平伸出來的。

**遮蔽結構（Occluded structure）**
- 是什麼：參考圖裡看不到、被擋住的部分，例如動物的肚子底下、產品的內部。
- 為什麼重要：看不到不代表不需要。R04 要求逐一決定：完整做、簡化做，還是省略。
- 小羊的例子：肚子底下的毛我們決定不放（`d.z < -0.35` 就跳過），因為遊戲鏡頭看不到，還能省面數。

**製作簡報（Production brief）**
- 是什麼：開工前寫下來的完整規格：用途、尺寸、面數預算、UV、材質、Rig、交付格式。
- 為什麼重要：大家對「做完」的定義要一致。模板在 `assets/production-brief.template.md`。

**需求複述（Recap，R04）**
- 是什麼：動手前把整份需求用你的語言整理一次，請你確認。
- 本專案的規則：只有**每個新資產第一次製作**需要完整複述；之後依回饋調整，只要一兩句話說明要改什麼。

**細節等級（Detail tier：low／medium／high）**
- 是什麼：低模、中模、高模。沒有全業界通用的數字，要看資產用途和鏡頭距離。
- 小羊的例子：手機 Web 遊戲，畫面上只有一隻靈獸，所以預算是成體 ≤ 8,000 三角形。

**預算（Budget）**
- 是什麼：事先約定的上限，例如三角形數、貼圖大小、材質數。
- 為什麼重要：手機效能和下載量有限。超過預算，載入會變慢、畫面會卡。

**工作紀錄（Worklog，R05）**
- 是什麼：每次工作後寫的紀錄：要求、做了什麼、怎麼驗證、結果、你的回饋。
- 為什麼重要：跨 session、跨電腦接手時，靠它知道做到哪、為什麼這樣做。本專案放在 `docs/art-worklog/`，用英文寫。

**回饋登錄（Feedback register）**
- 是什麼：把你的回饋整理成可重複套用的規則清單，在 `references/feedback-register.md`。
- 小羊的例子：「毛的間距 ÷ 半徑約 2.4 才有顆粒感」、「角要長在頭的外側」都記在那裡，做小獅時就不會再犯。

**交付物（Deliverable）／交接（Handoff）**
- 是什麼：交給下一個人（你、動畫、Unity）的檔案，以及讓對方能接手的狀態。
- 本專案的交付物（R11）：生成腳本（原稿，供學習）＋已驗證的版本化 `.blend`＋引擎用的 FBX。

**版本化檔名（Versioned filename）**
- 是什麼：每次產出都用新檔名，例如 `Lamb_Adult_v003.blend`，不覆蓋舊檔。
- 為什麼重要：改壞了可以回頭比較；回饋也能對應到「哪一版」。

**PASS／FAIL／NOT RUN／N/A**
- 是什麼：檢查結果的四種寫法：通過／失敗／沒做／不適用。
- 為什麼重要：沒做的檢查不能寫成通過。例如沒在 Unity 實際匯入，就寫 NOT RUN，不能說「應該沒問題」。

**重新開檔驗證（Fresh reopen）**
- 是什麼：存檔後，用一個全新的 Blender 程序打開那個檔案，再檢查一次。
- 為什麼重要：有些東西只存在記憶體裡、沒真的寫進檔案（例如外部貼圖路徑錯了）。只有重開才能證明檔案本身是好的。

## 2. 造型與物件

**剪影／輪廓（Silhouette）**
- 是什麼：把模型塗成全黑時看到的外形。
- 為什麼重要：在手機的小畫面上，大家主要靠剪影認出角色。NPR 模式特別看重這點。
- 小羊的例子：大頭、垂耳、蓬毛、捲角，光看黑影就知道是羊。

**比例（Proportion）／頭身比**
- 是什麼：各部位大小的相對關係，例如頭和身體的比例。
- 小羊的例子：幼體頭身比約 1:1，成體約 1:2。頭越大越像嬰兒，這是可愛感最主要的開關。

**打底（Blockout）／灰模（Clay）**
- 是什麼：只用簡單形狀先定大比例，還沒有細節的階段。灰模就是不上色、用灰色看形體。
- 小羊的例子：第 1 課的兩顆球。

**大、中、小形（Primary／Secondary／Tertiary forms）**
- 是什麼：大形是整體輪廓，中形是主要起伏，小形是細節。
- 為什麼重要：先把大形做對，再加中形，最後才加少量小細節。跳過大形直接堆細節，就會像第一版羊毛那樣「一串葡萄」。

**原點（Origin）／樞紐點（Pivot）**
- 是什麼：物件自己的中心點。移動、旋轉、縮放都以它為準。
- 為什麼重要：遊戲裡角色以原點對齊地面；嘴巴的原點在嘴中央，張嘴動畫才會從中心張開。
- 在 Blender：物件上那個橘色小點。Object → Set Origin 可以改。

**變換（Transform）：位置／旋轉／縮放（Location／Rotation／Scale）**
- 是什麼：物件在空間中的擺放方式，不改變網格本身的形狀。
- 在 Blender：按 `N` 開右側面板的 Item 分頁。

**套用變換（Apply transform）**
- 是什麼：把縮放、旋轉「烘」進網格，讓數值歸回 1 和 0，但外觀不變。
- 為什麼重要：非均勻縮放（X、Y、Z 縮放不同）會讓子物件變形、法線算錯、骨架動畫出問題。匯出到遊戲引擎前一定要套用。
- 在 Blender：`Ctrl+A`（Mac 是 `Control+A`）→ Rotation & Scale。

**父子關係（Parent／Child）、階層（Hierarchy）**
- 是什麼：子物件跟著父物件移動，但也能自己動。子物件記的是「相對於父物件的位置」。
- 小羊的例子：Mouth 是身體的子物件，身體走到哪嘴就跟到哪，但嘴可以自己張開。
- 在 Blender：先選子、再選父，`Ctrl+P`。

**集合（Collection）**
- 是什麼：Outliner 裡的資料夾，用來分組物件。
- 小羊的例子：早期把所有毛球放進 Wool 集合，可以一次隱藏。

**實例（Instance）**
- 是什麼：多個物件共用同一份網格資料。改一個，全部一起變。
- 為什麼重要：重複的零件（例如四顆一樣的扣子）用實例更省記憶體，也更好改。
- 在 Blender：`Alt+D` 複製出來的就是實例（`Shift+D` 是獨立複製）。

**修改器（Modifier）／修改器堆疊（Modifier stack）**
- 是什麼：疊加在網格上的效果，例如減面、加厚、包覆。依序由上往下計算。
- 為什麼重要：Apply 之前原網格不變，隨時可調或刪除，叫「非破壞式編輯」。順序不同結果就不同。
- 在 Blender：右側扳手圖示。

**基礎網格 vs 求值後幾何（Base mesh vs Evaluated geometry）**
- 是什麼：基礎網格是你實際編輯的點線面；求值後幾何是加上所有修改器之後，畫面真正顯示的結果。
- 為什麼重要：R03 要求兩者都檢查。例如在最後加一個 Triangulate 修改器把 n-gon 藏起來，基礎網格其實還是不合格。

**程序化來源（Procedural／generative source）**
- 是什麼：用程式或規則「生成」模型的原稿，例如我們的 `lamb_*.py`。
- 為什麼重要：改一個數字就能重做；同一套規則能用在新的動物上。交付時要和成品（`.blend`、FBX）分開說明各自的角色。

**Metaball（融合球）**
- 是什麼：每顆球是一個力場，場強加總後在「門檻值」的位置畫出表面，所以靠近的球會自動融成一團。
- 小羊的例子：羊毛、毛帽、脖子都是 metaball。實測發現表面大小只有設定半徑的 0.574 倍（stiffness 2），所以腳本裡要除以這個係數。
- 重要參數：Threshold（門檻）、Radius（半徑）、Stiffness（硬度，越大邊緣越分明）、Negative（負元素，會把附近挖掉）。

**曲線＋倒角（Curve + Bevel）**
- 是什麼：一條路徑，再給它粗細，就變成管狀物。每個點的 radius 可以控制那一段的粗細。
- 小羊的例子：羊角、微笑的嘴、披風的金繩都是這樣做的。

**Shrinkwrap（收縮包覆）**
- 是什麼：把網格的點推到另一個物件的表面上。
- 小羊的例子：披風。重點是 `OUTSIDE` 模式只推「在目標裡面」的點，所以草稿要做得比身體小。

**Solidify（加厚）**
- 是什麼：給一張薄片加上厚度。
- 小羊的例子：披風、立領。

**Decimate（減面）**
- 是什麼：自動合併點和面來降低面數。Collapse 模式會優先合併「外形改變最小」的地方。
- 小羊的例子：羊毛從約 20,000 個三角形減到 2,300～3,000。

**Boolean（布林運算）**
- 是什麼：用一個物件去加、減、交集另一個物件，例如挖洞。
- 為什麼要小心：結果常有很亂的佈線，R03 要求事後整理，不能直接交付。

## 3. 拓撲（Topology）

**點／邊／面（Vertex／Edge／Face）**
- 是什麼：網格的三種基本元素。點連成邊，邊圍成面。
- 在 Blender：Tab 進入編輯模式後，按 `1`／`2`／`3` 切換選取點、邊、面。

**三角形／四邊形／N 邊形（Triangle／Quad／N-gon）**
- 是什麼：三個點、四個點、五個點以上的面。
- 為什麼重要：遊戲引擎最後一律把面拆成三角形。N-gon 拆法不固定，容易出現奇怪的陰影；R03 規定交付的網格**不能有 n-gon**。
- 小羊的例子：圓柱和圓錐的蓋子預設是一整片 n-gon，收尾腳本會把它改成從中心放射的三角形。

**面數 vs 三角形數（Face count vs Triangle count）**
- 是什麼：一個四邊形算 1 個面，但等於 2 個三角形。
- 為什麼重要：說預算時一定要講清楚是哪一種。我們的預算一律用**三角形數**計算。

**拓撲（Topology）**
- 是什麼：點、線、面「怎麼連接」的整體結構，跟外形是兩回事：外形一樣，拓撲可以很好也可以很爛。
- 為什麼重要：好的拓撲讓模型容易修改、變形自然、光影平順。

**邊環／邊圈（Edge loop／Edge ring）**
- 是什麼：一串首尾相連、繞一圈的邊（loop）；或一圈平行的邊（ring）。
- 為什麼重要：動畫會彎折的地方（關節、嘴角）需要邊環才能自然變形。
- 在 Blender：編輯模式下 `Alt+點擊` 選邊環。

**佈線走向（Edge flow）**
- 是什麼：邊的排列順著形狀與肌肉的方向走。
- 為什麼重要：走向順，細分和變形時才不會出現皺折或凹陷。

**極點（Pole）**
- 是什麼：連接邊數不是 4 的點（例如 3 條或 5 條以上）。
- 為什麼重要：極點附近容易出現光影瑕疵，要放在不明顯、不會變形的地方。UV 球的南北極就是極點。

**三角扇（Triangle fan）**
- 是什麼：很多三角形共用同一個點，像扇子一樣散開。
- 為什麼重要：R03 特別禁止「從邊界上的某一點」拉出的長條扇形，因為會產生細長三角形和光影問題。從圓心放射的小扇形（例如小圓蓋）影響較小，可以接受。

**細長三角形（Sliver triangle）**
- 是什麼：很瘦很長的三角形。
- 為什麼重要：容易產生陰影錯誤、烘焙瑕疵，也浪費面數。

**格子填補／O 字環（Grid fill／O-grid）**
- 是什麼：用整齊的四邊形格子去填一個圓或洞，外圈是一圈環、中間是格子。
- 為什麼重要：R03 建議用這種方式處理圓形蓋子和洞口，而不是一大把三角扇。

**封閉流形／非流形（Manifold／Non-manifold）**
- 是什麼：封閉流形就是「像一顆完整的氣球、沒有破洞」。非流形是有破洞、一條邊連到三個以上的面、或面和面只靠一個點相連。
- 為什麼重要：3D 列印和某些運算需要封閉流形。但披風這種薄片本來就是開口的，R03 說要個別判斷，不能一律拒絕。

**開放邊界（Open boundary）**
- 是什麼：只連到一個面的邊，也就是網格的「破口」或邊緣。

**重疊面／零面積面／散點（Duplicate faces／Zero-area faces／Loose vertices）**
- 是什麼：位置完全重疊的兩個面／面積是零的面／沒連到任何面的點。
- 為什麼重要：都是會造成閃爍、烘焙錯誤或浪費的垃圾，交付前要清掉。
- 在 Blender：編輯模式 → Mesh → Clean Up；Merge by Distance 合併重疊點。

**自相交（Self-intersection）／穿插（Interpenetration）**
- 是什麼：模型的面互相穿過去。
- 小羊的例子：我們刻意讓零件互相插入（例如腿插進身體），避免接縫露縫；這是低模角色常見的作法，但要確認穿出來的部分看不到。

**細分（Subdivision）**
- 是什麼：把每個面切成更多更小的面，讓表面更圓滑。
- 為什麼重要：拓撲不好時，細分後的瑕疵會被放大。

**重拓撲（Retopology）**
- 是什麼：在高模表面上重新畫一層乾淨、低面數的網格。
- 小羊的例子：我們用 Decimate 自動減面代替，因為卡通低模、不會大幅變形；未來要做骨架動畫時，可能需要手動重拓撲關節附近。

**高模／低模（High poly／Low poly）**
- 是什麼：高模面數多、細節豐富，用來烘焙；低模面數少，真正放進遊戲。
- 小獅成體 v004 的例子：Meshy 的高模有 34 萬個三角形，複製一份減到 7,600 當低模，再把高模的顏色烘到低模的貼圖上。

**烘焙（Bake）**
- 是什麼：把「算出來的東西」（顏色、光影、法線）寫成一張圖片。從低模表面往外射光線，打到高模，把打到的資訊存進低模 UV 對應的像素。
- Selected to Active：選取的物件（高模）是「來源」，作用中的物件（低模）是「接收者」。
- Cage Extrusion（籠子外推）：射線從低模表面外推一點的地方出發，才打得到稍微凸出去的高模。太小會漏、太大會打到別的部位。
- Margin（邊緣擴張）：把每個 UV 島的顏色往外多塗幾個像素，縮小貼圖或 mipmap 時接縫才不會露出黑邊。
- 小技巧：只要顏色時，把來源材質改成「貼圖 → 自發光（Emission）」再烘 EMIT，就不受燈光和金屬度影響。

**多層次細節（LOD，Level of Detail）**
- 是什麼：同一個模型準備好幾個面數版本，鏡頭越遠用越低的那個。
- 本專案：畫面上永遠只有一隻靈獸、距離固定，所以目前不需要 LOD。

**變形（Deformation）**
- 是什麼：模型被骨架帶動時彎曲、擠壓的變化。
- 為什麼重要：會變形的地方要有足夠的邊環；不變形的硬物可以很省。

**三角化與求值對角線（Triangulation／Evaluation diagonal）**
- 是什麼：四邊形拆成兩個三角形時，可以沿兩條對角線中的任一條切。
- 為什麼重要：切法不同，光影就不同。烘焙時和遊戲中用的切法要一致，否則法線貼圖會出錯。

## 4. UV

**UV／UV 貼圖（UV map）**
- 是什麼：把 3D 表面「攤平」到一張 2D 平面上的對照表，告訴電腦「表面上每一點對應貼圖的哪一個位置」。U、V 就是 2D 平面的兩個軸（X、Y 已經被 3D 用掉了）。
- 為什麼重要：沒有 UV 就不能貼圖。R03 規定**每個網格都要有 UV**，NPR 和 PBR 都一樣。
- 小羊的例子：目前顏色靠頂點色，但花紋遮罩要畫在羊毛中間，就需要 UV。

**展開（Unwrap）**
- 是什麼：產生 UV 的動作，就像把紙盒拆開壓平。
- 在 Blender：編輯模式選取全部 → `U` → Unwrap 或 Smart UV Project。

**接縫（Seam）**
- 是什麼：展開時「剪開」的邊。
- 為什麼重要：接縫處貼圖會斷開，要藏在不明顯的地方（腋下、背後）。

**UV 島（Island）**
- 是什麼：展開後一塊塊連在一起的區域。

**拉伸／變形（Stretch／Distortion）**
- 是什麼：攤平時某些地方被拉長或擠壓，貼圖就會變形。
- 怎麼檢查：貼上棋盤格貼圖（Checker），方格應該大小一致、是正方形。

**重疊（Overlap）**
- 是什麼：兩塊 UV 島疊在一起，會共用同一塊貼圖。
- 為什麼重要：預設不能重疊（烘焙會出錯）。刻意重疊（例如左右對稱共用）要事先確認並記錄。

**鏡像／堆疊 UV（Mirrored／Stacked UV）**
- 是什麼：左右兩邊或多個相同零件的 UV 疊在一起，省貼圖空間。
- 代價：兩邊的貼圖一定一模一樣，也不能烘焙獨特的光影。

**貼圖密度（Texel density）**
- 是什麼：單位面積的模型表面分到多少貼圖像素。
- 為什麼重要：密度不一致時，有的地方清楚、有的地方糊。臉這種重要的地方可以刻意給高一點。

**間距／邊距（Padding／Margin）**
- 是什麼：UV 島之間留的空隙，以及島邊緣往外延伸的顏色。
- 為什麼重要：貼圖縮小（Mipmap）時，相鄰的島會「滲色（Bleed）」，間距不夠就會看到接縫有雜色。

**0–1 空間**
- 是什麼：UV 平面上，從 0 到 1 的那一格正方形，對應一整張貼圖。

**圖集／UV 頁（Atlas／UV sheet）**
- 是什麼：把好幾個零件的 UV 放在同一張貼圖上。
- 注意：「幾張圖集」和「每張圖集有幾個通道」是兩回事。一張圖集可以有 BaseColor、Normal 等好幾個檔案。

**正方形解析度、2 的次方（Square resolution、Power of two）**
- 是什麼：貼圖邊長用 512、1024、2048 這種 2 的次方，而且長寬相同。
- 為什麼重要：GPU 壓縮和 Mipmap 最有效率。本專案貼圖上限 1024²，花紋遮罩 ≤ 512²。

**UDIM**
- 是什麼：UV 不只用 0–1 一格，而是用很多格（1001、1002…），每格一張貼圖。
- 用途：影視高解析資產。手機遊戲一般用不到。

**光照貼圖 UV（Lightmap UV）**
- 是什麼：第二組 UV，專門給引擎烘焙靜態光照，必須完全不重疊。
- 為什麼重要：Unreal 使用靜態光照時需要；Unity 可以在匯入時自動產生（R12）。

**Smart UV Project（智慧 UV 投影）**
- 是什麼：Blender 依面的角度自動切接縫、展開的工具。
- 本專案：收尾腳本用它幫每個網格自動展 UV。對有機形狀夠用，要畫精緻花紋時再手動調整接縫。

## 5. 材質與著色（兩種模式共通）

**材質（Material）／Shader**
- 是什麼：決定表面「看起來怎樣」的設定。Shader 是實際計算顏色和光影的程式。
- 為什麼重要：同一個網格，換材質就能從塑膠變成金屬、從寫實變成卡通。

**材質槽（Material slot）／繪製呼叫（Draw call）**
- 是什麼：一個物件可以有好幾個材質，每個材質通常就是 GPU 的一次「繪製呼叫」。
- 為什麼重要：手機上繪製呼叫越少越順。所以 GDD 規定**單一材質**。

**Shader Editor／節點（Node）**
- 是什麼：用「方塊＋連線」組合材質的編輯器。每個節點做一件事，連線傳遞數值。
- R01 要求：由左到右排好（座標 → 貼圖 → 調整 → BSDF → 輸出），用 Frame 分區、命名清楚，不能疊在一起。
- 在 Blender：上方的 Shading 分頁，下半部就是。

**節點群組（Node group）、框（Frame）、轉接點（Reroute）**
- 是什麼：群組把一堆節點包成一個；框是用來分區的標籤方塊；轉接點讓連線轉彎、變整齊。

**Texture Coordinate → Mapping → Image Texture**
- 是什麼：貼圖的標準接法：先取得座標（通常是 UV），經過 Mapping（可以移動、旋轉、縮放貼圖），再去讀圖片。
- R01 要求：每一張圖片都要接到 Mapping；同一組貼圖共用同一個 Mapping，對齊才不會跑掉。
- 在 Blender：裝了 Node Wrangler 外掛時，選圖片節點按 `Ctrl+T` 會自動接好。

**色彩空間：sRGB／Non-Color／Linear**
- 是什麼：數字要怎麼被解讀。sRGB 是「給人眼看的顏色」；Non-Color 是「純資料，不是顏色」。
- 為什麼重要：BaseColor 用 sRGB；Normal、Roughness、Metallic、遮罩用 Non-Color。設錯的話數值會被偷偷改掉，光影就不對。
- 小羊的例子：FBX 重新匯入時，固定色被做了色彩空間轉換，象牙色變得偏深，就是這個原因。

**頂點色／顏色屬性（Vertex color／Color attribute）**
- 是什麼：直接存在每個頂點（或每個面角）上的顏色資料，不需要貼圖。
- 小羊的例子：我們的 `Mask` 屬性。

**遮罩（Mask）**
- 是什麼：用來「標記區域」的資料，本身不是最後的顏色。
- 小羊的例子：配色遮罩。A=1 時 R、G、B 分別代表主色、副色、點綴色；A=0 時 RGB 就是固定色。內襯用 0.45 表示「該色槽的 45% 亮度」。

## 6. PBR 模式

**PBR（Physically Based Rendering，物理式渲染）**
- 是什麼：用接近真實物理的規則計算光線怎麼被表面反射、吸收。
- 為什麼重要：同一個材質，在任何光線下都會「看起來合理」。寫實遊戲和影視的標準作法。

**BSDF／Principled BSDF**
- 是什麼：描述「光打到表面後往哪裡散開」的函數。Principled BSDF 是 Blender 的萬用 PBR 節點，把常用參數都集中在一起。
- 「完整 BSDF 思維」：用顏色、粗糙度、金屬度、法線等參數去描述真實材質，而不是直接畫出光影。

**BaseColor／Albedo（基礎色）**
- 是什麼：表面本身的顏色，**不能包含光影、高光、陰影**。
- 常見錯誤：直接拿照片當 BaseColor，照片裡的光影就被「凍」進去了。

**Normal map（法線貼圖）**
- 是什麼：用 RGB 記錄「每個像素的表面朝向哪裡」，讓平面看起來有凹凸，但不增加面數。
- 切線空間（Tangent space）：最常用的一種，記錄的是「相對於表面」的方向，所以模型變形時還能用。
- OpenGL／DirectX：兩種綠色通道方向相反。Blender 和 Unity 用 OpenGL（Y+），Unreal 用 DirectX（Y−）。給 Unreal 時要翻轉綠色通道或在匯入時設定。
- 要用 Non-Color，並接到 Normal Map 節點。

**Roughness（粗糙度）**
- 是什麼：0 是鏡面般光滑，1 是完全霧面。
- 小技巧：粗糙度的細微變化（指紋、磨損）比顏色變化更能讓材質看起來真實。

**Metallic／Metalness（金屬度）**
- 是什麼：是不是金屬。通常只用 0 或 1，中間值只用在金屬和非金屬交界處（例如鏽斑邊緣）。
- R02 提到：整片非金屬的物件，可以交付一張全黑（Metallic=0）的貼圖，這是合理的。

**ORM 打包（Channel packing）**
- 是什麼：把 Occlusion、Roughness、Metallic 三張灰階圖塞進一張圖的 R、G、B 三個通道，省檔案。
- R02 規定：就算引擎要 ORM，也要保留四張可編輯的原始貼圖。

**Emission（自發光）、Alpha（透明度）**
- 是什麼：自發光是表面自己發光；Alpha 是透明程度。
- R02 提醒：Alpha 通道可以用來當發光遮罩，但不能因此自動接到透明度，兩者功能不同。

**Displacement／Height／Bump（置換／高度／凹凸）**
- 是什麼：置換會真的推動頂點、改變輪廓；Bump 和 Normal 只改變光影、不改輪廓。

**Transmission（穿透）、Subsurface（次表面散射）、Coating／Clearcoat（塗層）**
- 是什麼：光線穿過玻璃；光線進入皮膚、蠟後在裡面散開；汽車烤漆那層亮光漆。

**程序材質（Procedural material）**
- 是什麼：用數學節點（噪點、漸層）即時算出來的材質，不是圖片。
- 為什麼重要：好調整，但遊戲引擎看不懂 Blender 的節點，所以要「烘焙」成圖片才能交付。

**烘焙（Bake）**
- 是什麼：把「算出來的效果」存成圖片。
- 兩種要分清楚（R02）：
  - 同一網格的材質烘焙：把程序材質存成圖片。
  - 高模投射到低模：把高模的細節（凹凸）投射到低模的法線貼圖上。這才是「高模烘低模」。

**籠子／射線距離（Cage／Ray distance）**
- 是什麼：高模投射到低模時，從低模往外打射線去找高模表面。籠子是稍微膨脹的低模，決定射線從哪裡出發、射多遠。
- 設錯時：會打到旁邊的零件，或打不到東西，貼圖出現破洞或錯誤的細節。

**烘焙代理（Bake proxy）**
- 是什麼：專門為了烘焙而準備的複製網格（例如把零件拆開避免互相投射）。
- R02 提醒：代理和最終交付的網格，法線和三角化方式必須一致，否則烘出來的法線貼圖套回去會錯。

**切線基底（Tangent basis）**
- 是什麼：每個點上「表面的方向座標系」，法線貼圖要靠它解讀。
- 為什麼重要：烘焙和顯示時用的基底不同，法線貼圖就會出現奇怪的明暗。

## 7. 平滑與法線

**法線（Normal）**
- 是什麼：表面在某一點「正對外面」的方向。光影就是根據法線和光線的夾角算的。
- 小羊的例子：第 2 課讓眼睛轉 22° 貼合臉，就是讓眼睛轉到跟臉部表面的法線一致。

**平滑著色／平面著色（Shade Smooth／Shade Flat）**
- 是什麼：平滑著色把相鄰面的法線平均，表面看起來圓滑；平面著色每個面一個方向，看得出一個個切面。
- 重點：只改光影，不改面數。
- 在 Blender：物件右鍵 → Shade Smooth／Shade Flat。

**依角度平滑（Auto Smooth／Smooth by Angle）**
- 是什麼：夾角小於設定值的邊平滑，大於的保持銳利。
- 為什麼重要：硬物（盒子、機械）需要平的面加銳利的邊，同時曲面要圓滑。

**銳邊（Sharp edge）／硬邊（Hard edge）**
- 是什麼：手動標記為「這裡不平滑」的邊。

**分離／自訂法線（Split normals／Custom normals）**
- 是什麼：同一個點在不同面上可以有不同的法線方向，讓銳邊兩側各自正確。自訂法線就是手動指定方向。
- NPR 相關：分離的法線會讓「沿法線外推」的描邊在銳邊處斷開，所以要另外準備平滑過的描邊法線。

**Weighted Normal（加權法線）**
- 是什麼：依面積加權計算法線，讓大面更平整。
- R02 提醒：它是可選的修飾，不能取代「決定哪裡要銳邊」這件事。

## 8. NPR／卡通模式

**NPR（Non-Photorealistic Rendering，非寫實渲染）**
- 是什麼：刻意不追求寫實的風格，例如卡通、手繪、水彩。
- 本專案：靈獸採用 NPR 卡通模式（見 `art/ART_PROFILE.md`）。

**卡通著色／賽璐珞著色（Toon shading／Cel shading）**
- 是什麼：把連續的明暗變化切成幾段硬邊的色塊，像動畫賽璐珞片。
- 為什麼這樣：畫面乾淨、可愛、容易讀，也很省效能。

**色階（Ramp）／光帶（Bands）**
- 是什麼：決定「亮度幾以上算亮面、幾以下算暗面」的對照表。通常 2～3 段。
- 在 Blender：Color Ramp 節點，插值模式設 Constant 就是硬切。

**Shader to RGB**
- 是什麼：EEVEE 專用節點，把「打過光的結果」轉成顏色，才能再接 Color Ramp 做卡通色階。Cycles 沒有這個節點。

**Toon 思維**
- 是什麼：用形狀和平塗色塊表達，而不是靠細節和光影。三角形花在剪影上，顏色分區清楚、不畫光影，讓引擎產生光帶。

**描邊（Outline）**
- 是什麼：角色外圍那圈深色的線，卡通風格的關鍵。三種常見作法：
  - **反向外殼（Inverted hull）**：複製一層稍微膨脹的網格，法線翻轉、只畫背面，看起來就像一圈邊線。Blender 裡可用 Solidify（勾選 Flip Normals）加上背面剔除做出來。
  - **Shader 外推（Shader pass）**：在 shader 裡多畫一次，把頂點沿法線往外推。Unity URP 常用。
  - **後處理邊緣偵測（Post-process edge detection）**：整個畫面算完後，依深度或法線的變化找出邊緣再畫線。Unreal 常用。
- 為什麼重要：沒有描邊，卡通角色在背景上容易糊在一起。

**背面剔除（Back-face culling）**
- 是什麼：不畫背對鏡頭的面。反向外殼描邊就是靠它，只露出外殼的「背面」那一圈。

**平均法線（Averaged／smoothed outline normals）**
- 是什麼：把同一個位置上各個分離法線平均成一個方向，存到頂點色或備用 UV，專門給描邊用。
- 為什麼重要：避免描邊在銳邊或零件交界處斷開、出現尖刺。

**Freestyle**
- 是什麼：Blender 內建的線條渲染器，可以在算圖時畫出輪廓線。只在 Blender 算圖有效，遊戲引擎用不到，所以只能當預覽。

**調色盤換色（Palette swap）**
- 是什麼：同一個模型只改顏色參數，換出不同配色。
- 小羊的例子：8 組配色就是靠配色遮罩加上材質參數完成，不用重做貼圖。

**調色盤貼圖（Palette texture／Gradient atlas）**
- 是什麼：另一種 NPR 上色法：做一張很小的色票圖，把每個零件的 UV 縮成一個點，放到對應的顏色格子上。

## 9. Rig 與動畫

**Rig（綁定）**
- 是什麼：讓模型能被操作和做動畫的整套控制系統：骨架、控制器、限制。

**Armature（骨架）／Bone（骨頭）**
- 是什麼：Armature 是一組骨頭的集合；骨頭帶動網格變形或移動。
- R10 規定：動畫師要操作的控制器必須是 Armature 的骨頭，在 Pose Mode 操作；不能用 Object Mode 的空物件代替。

**Pose Mode／Edit Mode（骨架）／Rest pose**
- 是什麼：Edit Mode 調整骨頭的「原始位置」；Pose Mode 擺姿勢和打關鍵影格；Rest pose 是原始的待機姿勢。

**Pose bone／控制骨 vs 變形骨（Control bone vs Deform bone）**
- 是什麼：變形骨直接帶動網格；控制骨是給人操作的把手，再透過限制去帶動變形骨。

**自訂形狀（Custom shape）**
- 是什麼：讓控制骨在畫面上顯示成圓圈、箭頭等好選取的形狀。R10 提醒：它只是外觀，操作的還是骨頭本身。

**限制（Constraint）／驅動（Driver）**
- 是什麼：限制是「讓 A 跟著 B」、「旋轉不能超過 30°」這類規則；驅動是用數學式把一個數值連到另一個（例如往上拉蓋子 → 蓋子旋轉）。

**關鍵影格（Keyframe）**
- 是什麼：在某個時間點記錄某個數值，中間的時間由電腦自動補間。
- 在 Blender：滑鼠停在欄位上按 `I`。

**變換鎖定（Transform lock）vs 選取鎖定（Selection lock）**
- 是什麼：變換鎖定是「這個軸不能動」；選取鎖定是「根本選不到」。
- R06／R10 提醒：可以用變換鎖定限制動作範圍，但交付時不能鎖選取。

**區域／世界空間（Local／World space）**
- 是什麼：以物件自己的方向為準，或以整個世界的方向為準。

**權重繪製（Weight paint）／蒙皮（Skinning）**
- 是什麼：決定每個頂點受哪幾根骨頭影響、影響多少。
- 本專案：GDD 計畫四足（羊、獅）共用一套骨架，所以權重要乾淨，動畫才能互相套用。

**形狀鍵（Shape key）／混合形狀（Blend shape）**
- 是什麼：記錄網格的另一種形狀，用滑桿在兩者間切換。適合做表情，例如眨眼、張嘴。Unity 叫 Blend Shape。

## 10. 交付與遊戲引擎

**.blend**
- 是什麼：Blender 的原生檔案，存著整個場景：網格、材質、骨架、設定。
- 本專案（R11）：交付已驗證的版本化 `.blend`。不要放進 Unity 的 `Assets/` 資料夾，否則 Unity 會試著用 Blender 匯入它。

**FBX**
- 是什麼：遊戲引擎最通用的 3D 交換格式，Unity 和 Unreal 都支援。能帶網格、UV、頂點色、骨架、動畫。

**glTF／GLB**
- 是什麼：開放標準的 3D 格式，常用於網頁。Unreal 5 可直接匯入；Unity 需要另外裝套件。

**座標軸轉換（Axis conversion：Forward／Up）**
- 是什麼：Blender 是 Z 朝上；Unity 是 Y 朝上；Unreal 是 Z 朝上但以 X 為前方。匯出時要設定對應的軸。
- 小羊的例子：角色在 Blender 面向 −Y，用 Forward −Z、Up Y 匯出，到 Unity 剛好面向正前方。

**單位比例（Unit scale）**
- 是什麼：Blender 和 Unity 的 1 單位是 1 公尺；Unreal 的 1 單位是 1 公分。
- 為什麼重要：設錯會變成大 100 倍或小 100 倍。

**匯出時套用變換（Apply transform on export／bake space transform）**
- 是什麼：匯出時把軸向轉換直接烘進網格。
- 為什麼重要：不設定的話，在 Unity 裡物件根部會多一個 −90° 的 X 旋轉，很多新手都被這個坑過。

**平滑群組（Smoothing groups）**
- 是什麼：告訴引擎哪些面要平滑連接的資訊。
- 為什麼重要：FBX 匯出時 Smoothing 設成 Face，Unreal 才不會警告缺少平滑資訊。

**頂點色匯入（Vertex color import）**
- 是什麼：引擎匯入時要不要保留頂點色。Unity 預設會讀；Unreal 要在匯入選項設 Replace。

**匯入測試（Import test）**
- 是什麼：實際把匯出檔放進引擎，檢查朝向、比例、顏色、面數、描邊。
- R12：沒有實際匯入，就記為 NOT RUN。

**選取與 Extras（Selection／Overlays／Extras，R06）**
- 是什麼：交付的檔案裡，所有物件和集合都要能被選取；3D 視窗的 Overlays 和 Extras（顯示燈光、相機等）要開著。
- 為什麼重要：接手的人打開檔案，不能發現東西選不到、燈光找不到。

**打包與相對路徑（Pack／Relative path）**
- 是什麼：打包是把外部貼圖塞進 `.blend`；相對路徑是用「相對於 .blend 的位置」記錄貼圖。
- 為什麼重要：換電腦打開時，貼圖才不會遺失。R09 要求貼圖按物件類別分資料夾整理。

## 11. Blender 介面

**物件模式／編輯模式（Object Mode／Edit Mode）**
- 是什麼：物件模式操作整個物件；編輯模式修改網格的點線面。按 `Tab` 切換。

**視窗著色：線框／實心／材質預覽／算圖（Wireframe／Solid／Material Preview／Rendered）**
- 是什麼：右上角四顆球。
- 小羊的例子：工作時用 Solid 加 Object 顏色看零件；跑完收尾腳本後，用 Material Preview 看配色遮罩的真實效果。

**EEVEE／Cycles**
- 是什麼：Blender 的兩個算圖引擎。EEVEE 快、即時，支援 Shader to RGB（卡通）；Cycles 是光線追蹤，寫實但慢。

**工作區（Workspace）／畫面（Screen）**
- 是什麼：上方的 Layout、Shading、Scripting 等分頁。每個分頁有自己的 3D 視窗和設定。
- 小羊的例子：腳本只改了 Scripting 分頁的視窗，切回 Layout 看不到顏色，就是這個原因。

**Outliner（大綱）**
- 是什麼：右上角的物件清單，可以選取、改名、隱藏、整理集合。

**Statistics（統計資訊）**
- 是什麼：Overlays 選單裡勾選後，左上角會顯示點、面、三角形數。檢查預算時用。

**放樣（Loft）**
- 是什麼：沿著一條方向，每隔一段放一個截面（一圈點），再把相鄰兩圈接成四邊形，拼出一個管狀的形體。
- 小獅成體 v005 的例子：從參考模型量出每一段的背高、肚子高、寬度，做成一張「輪廓表」，每一列就是一圈；改表上的數字就能直接改輪廓。
- 跟 metaball 比：放樣的輪廓完全照數字走（不會鼓起來或黏在一起），面也整齊；metaball 適合要「融在一起」的團塊。

**程序化雜訊（Procedural noise）**
- 是什麼：用公式算出來的、看起來隨機但連續的灰階圖案（Noise Texture 節點）。可以在 3D 空間裡算，不會重複。
- 小獅的毛流：雜訊在上下方向拉長（z 的密度小）→ 一條條往下的紋路，像梳過的毛；再烘焙到 UV 上變成花紋遮罩貼圖給引擎用。

**sRGB 與 Linear**
- 是什麼：同一個顏色的兩種數字寫法。我們眼睛看的、色票上的數字是 sRGB；材質運算用的是 Linear（「光的量」）。
- 為什麼重要：把 sRGB 數字直接當 Linear 用，顏色會變得很淡（v005 第一次預覽就是這樣）。要先換算。
